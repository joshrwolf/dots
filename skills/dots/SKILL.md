# dots

Use `dots` for supported workflows before assembling equivalent shell/API calls. Native tools remain available for unsupported operations or useful follow-up.

Prefer `dots COMMAND --help` for command-specific syntax. The [generated command reference](references/commands.md) is an on-demand lookup, not required reading: search for the command and read only its section. Do not load the reference wholesale when loading this skill. Installed help is authoritative if it differs.

For agent workflows, request `--json`; generated dots follow-up commands preserve JSON mode.

Use the task's explicit target or working directory; do not silently substitute another checkout or workspace. Follow the references and next commands returned by the tool. Treat partial or unavailable evidence as such. Tool availability does not authorize mutations beyond the user's request.

`dots task` keeps one work list per project, shared by every session and linked worktree: tasks, dependencies, claims, results, and links to PRs or tickets. Claim a task before working on it or delegating it; workers report results to the session that records them. The `goals` skill covers planning, handoff, and acceptance.

Add every PR you create or start working on to the watch list with `dots github watch add <url> --json`. Adding is idempotent and records intent only: it does not authorize CI fixes, monitoring, or merging. Remove a PR only when explicitly asked or to correct a mistake.

## Available workflows

- `dots output`: Publish and inspect immutable project evidence; publication does not accept tasks. Commands: publish, list, revisions, show, path, attach, detach, integrity, purge.
- `dots project`: Initialize the workspace catalog and explicitly bind local Git projects. Commands: init, register, list, resolve, bind, unbind, rebind.
- `dots github`: Inspect GitHub CI evidence and PR review threads, and keep a PR watch list. Commands: ci, reviews, watch.
- `dots task`: Track shared, claimable work for a project across concurrent sessions. Commands: goal, list, ready, show, result-event, events, event-kinds, add, claim, release, update, review, done, hold, drop, reopen, ref, dep.
- `dots attention`: Ask the user durable questions about goal work and record goal decisions. Commands: raise, supersede, withdraw, answer, incorporate, decide, show, list, decisions, view.
- `dots memory`: Read and publish shared knowledge snapshots across machines. Commands: init, context, status, read, write, remove, publish, search, project, reconcile, inspect, convert.
- `dots substrate`: Configure and inspect this machine's connection to the shared cross-machine remote. Commands: init, status.
- `dots review`: Review a repository's changes in threads anchored to exact revisions, across its worktrees. Commands: start, open, inbox, list, show, add, reply, set, draft, discard, submit, mark, unmark, look, refresh, remove.
